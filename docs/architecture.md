# 棚と書籍の物理モデル

AndroidはComposeの画面とFilamentの描画を使い、Node.js / TypeScriptのAPIと連携する。棚データはschema 4だけを扱う。後方互換・データ移行は行わない。

## 責務

| 層 | 保持するもの |
| --- | --- |
| `core` | 棚の内寸、書誌、実寸、配置、入力検証、履歴、JSON |
| `renderer-api` | 共通の場面、カメラ、座標変換、選択判定、画像資源 |
| `renderer-filament` | GPU描画、素材の読み込み、描画資源の寿命 |
| `app` | Compose画面、操作、原子的な端末保存、API通信 |
| `server` | 認証・認可、書誌検索、クラウド保存、公開棚、通報、永続化 |

## 寸法と配置

- 棚は1区画。内寸は幅240〜1800 mm、高さ120〜800 mm、奥行100〜600 mm。木とラベンダーの素材を選べる。
- 座標は100 mmを1単位とする。X=0が棚の中央、床はY=0.25。天板・側板・背板を個別に配置し、棚の内寸を変えても板厚は固定する。
- 本は幅・高さ・厚みを持ち、背表紙・面陳・平積みで占有寸法が変わる。厚みは実測、書誌由来の自動値、ページ数による推定の順で決める。
- 平積みは各本の厚みを合計し、最大の幅・奥行を使う。同じ本は棚に1回だけ置ける。小物は最大6個。
- 棚からのはみ出しと本同士の重なりを拒否する。本を自動で縮小・移動せず、画面に収める調整はカメラで行う。
- 編集は文書全体を検証してから確定する。拒否した操作は履歴に入れない。Undoは最大100件で、新しい操作がRedoを消去する。

## 画像と保存

本はすべて登録した書誌（`books`）だけで構成し、同梱の見本書籍や見本の棚は持たない。新規インストールは空の棚から始まる。すべての本は1つの汎用モデル`models/book.glb`を実寸へ変形して描画する。表紙は書誌の書影を使い、ない場合と背表紙は書名・著者から生成する。外部書影は許可したホストと容量上限の範囲で取得する。

端末保存は`AtomicFile`を使う。破損・非対応形式は読み込まず、保存失敗時には未保存の編集を保持して再試行する。棚の置換は現在の編集セッション内で取り消せる。

積読とお気に入りは端末の`library.json`に保存し、アカウントなしで使える。積読は書誌と見つけた公開棚のID、お気に入りは公開棚のIDだけを持ち、それぞれ最大500件。書誌は棚と同じ検証を通す。読み込めないファイルは上書きせず、変更を止める。開こうとした棚が非公開になっていた場合は、書誌を残して棚IDだけを消す。

## 厚みの自動入力

優先順は **実測の手入力 → 書誌の寸法 → ページ数の推定**。自動値は`automaticThicknessMm`と出典`bibliography`を持ち、`measuredThicknessMm`と混同しない。手入力欄を空にすると自動値へ戻る。

ISBNのチェック桁を検証し、ISBN-10は13へ正規化する。まずopenBDの該当版を検索し、ページ数が欠けている場合や未収録時はOpen LibraryのISBN版を参照する。作品単位の別版の表紙やページ数を混ぜない。書名検索はOpen Library検索。

- [openBD仕様](https://openbd.jp/spec/) の`Measure`（高さ01・幅02・背幅03）と`Extent`（ページ）を使用。[ONIXの単位](https://ns.editeur.org/onix/en/50/mm)はmm・cm・inをmmへ変換する。
- [Open Library Editions / ISBN API](https://openlibrary.org/dev/docs/api/books)のページ数、版の表紙、明示的な単位付きH×W×Tを使用。軸の並べ替えや単位なしの推測はしない。
- 寸法未収録時は文庫等の判型を目安にする。判型も不明なら128×188 mm、ページ数も不明なら仮240ページ。厚みの最終推定は`ページ数 / 2 × 0.09 + 2.6 mm`。紙や製本によって誤差がある。
- 登録画面とサイズ修正画面に、自動の厚みと根拠を表示する。ページ数を変更すると推定厚みも即座に更新する。確定した寸法が棚や隣の本に重なる場合は保存しない。

クラウドの下書きは非公開。公開操作で棚上の本・小物・棚名・ひとことだけを抽出し、編集中の変更や未配置の蔵書は自動公開しない。Androidとサーバーは同じ寸法・配置・形式を検証する。[共有仕様](community.md)を参照。
