## 3. 誰に、どのような体験を届けるか【今回の整理案】

### 想定する利用者

読んだ本や読みたい本を自分の本棚として整理し、後から見返したい人を想定する。その中でも、読了した本について内容を思い出したり、自分の理解を確かめたりしたい人に、クイズという任意の入口を用意する。

対象年齢、読書量、書籍ジャンルなどによる限定は、現時点の確認範囲では設けない。利用者像の詳細は今後の検証対象とする。

### 中心となる利用の流れ

```text
本を登録する → 本棚を整える → 棚や本の情報を見返す
                                  ↓ 任意
                         読んだ本のクイズに取り組む
                                  ↓
                         結果を確認して本棚へ戻る
```

クイズに参加しなくても、本の登録と棚づくりだけで利用が成立する構成にする。正答数を増やすことを本棚の利用条件にはしない。

この構成で確かめたいのは、「自分の本棚を作り続けたい」という動機と、「そこにある本をもう一度振り返りたい」という動機がつながるかどうかである。これは検証する仮説であり、利用者調査で確認済みの効果ではない。

## 4. 機能と優先順位【今回の提案】

| 優先順位 | 機能 | 最初に実現する体験 |
| --- | --- | --- |
| 中核 | 本の登録・編集・削除 | 自分の本を登録し、入力の誤りを修正できる。 |
| 中核 | 本棚の表示と整理 | 登録した本を一覧で見返し、自分なりに整理できる。 |
| 中核 | 本ごとの情報表示 | 棚から本を選び、登録内容を確認できる。 |
| 中核 | 登録内容の保存 | 利用を中断しても、本と棚の情報を再び開ける。 |
| 補助 | 読書クイズ | 読んだ本について、利用者が選んだときに出題する。 |
| 補助 | クイズの結果と解説 | 解答後に、答えとその根拠を確認できる。 |

本棚の整理方法を、並べ替え、複数の棚への分類、タグ付けなどのどれにするかは、未確認の既存仕様を推測で埋めず、実装前に選ぶ。書籍検索やISBN入力も登録方法の候補だが、本書では採用済み機能として扱わない。

## 5. 読書クイズの設計方針【今回の提案】

### 読んだ本を振り返るために使う

出題対象は、利用者が読んだと指定した本に限る。クイズを開くかどうかは利用者が選び、未読の本の内容を意図せず表示しない導線にする。

具体的な出題数、選択式・記述式の別、難易度、再挑戦の条件は、本書では固定しない。まず少数の問題を用意し、解答して終わるだけでなく、本を振り返るきっかけになるかを確かめる。

### 正解を示せる問題と、感想を尋ねる問いを分ける

正誤判定をする問題には、正解と解説の根拠を用意する。作品の解釈や感想のように複数の答えが成立する問いを、根拠なく一つの正解に押し込めない。

書名だけから内容を推測して正解を作る運用は採用しない。問題の入手方法、対象書籍、確認方法が決まるまでは、確認済みの少数の問題による試作を優先する。AIによる自動生成を採用するかどうかも、既存の決定として扱わない。

### 本棚の操作を妨げない

クイズを解かなくても、本の登録、編集、棚の閲覧を続けられるようにする。得点に応じた機能開放、連続利用の報酬、他者との競争は、今回のMVP案には含めない。

## 6. 最初の実装範囲と検証方法【今回の提案】

### 第1段階：本棚だけで利用が成立する試作

本を登録し、棚に表示し、情報を修正し、保存した内容を再び開くまでをつなぐ。見た目の細部や追加機能より、少数の本で一連の操作を迷わず完了できることを優先する。

| 確認項目 | 到達条件 |
| --- | --- |
| 登録と表示 | 登録した本が棚と詳細表示に反映される。 |
| 編集と削除 | 操作の結果が保存内容にも反映され、削除対象を確認できる。 |
| 保存と再開 | 画面を閉じて再開しても、保存した登録内容と棚の状態が一致する。 |
| 棚の整理 | 採用した整理方法で本を移動・分類でき、意図しない消失がない。 |

### 第2段階：読書クイズの小規模な試作

対象となる本と、正解を確認済みの問題を絞り、出題、解答、結果・解説、本棚への復帰までをつなぐ。

検証では、問題を大量に増やす前に、出題対象を取り違えないこと、答えの根拠を確認できること、クイズを途中でやめても棚づくりへ戻れることを確かめる。そのうえで、実際の利用者が本を振り返るために再び使うかを観察する。利用目標や成功率の数値は、根拠なく設定しない。

### 今回の成果物の範囲

今回追加するのは、この企画書のみである。アプリ本体、問題データ、認証、配信環境は実装していない。既存コードや試作品が完成しているとも断定しない。
