# Shelfie サービス企画書

> 変わりたくない自分を本棚に委託しろ。

2026年9月7日｜企画案

## 1. 企画概要

**Shelfieは、好きな本と装飾を組み合わせて自分だけの本棚を作り、その本棚を自己紹介として共有できるアプリである。** 他人の本棚を訪ね、気になった本を自分の積読に迎えることで、本と人との出会いをつなぐ。

ずっと好きでいたいもの、自分の一部として残しておきたい本を、棚の形で預けておく。本人が近況や自己紹介を発信し続けなくても、選んだ本、並べ方、棚の雰囲気がその人を伝える。新しい本に出会うたびに、以前の好みを捨てる必要はない。

提供するのは、自分を表す棚を持つ楽しさと、誰かの棚から次の一冊に出会う体験である。読了冊数を増やすことや、積読を早く消化することは目的にしない。

## 2. 対象者と提供価値

主な対象は、好きな本を自分の趣味や価値観の一部として大切にし、それを人に伝えたい利用者である。読書量の多さは問わない。少数の本でも、選び方と飾り方で自分らしい棚を作れることを重視する。

初期検証では、次のニーズを想定する。

| 利用者のニーズ | Shelfieが提供する体験 |
| --- | --- |
| 自分を長い文章で説明する代わりに、好きなものを見せたい。 | 選書と装飾をまとめた本棚を、プロフィールとして渡せる。 |
| 大切な本を、次々と更新する情報の中に埋もれさせたくない。 | 自分で選んだ配置を保ち、更新しなくても見返せる棚を持てる。 |
| 本を並べたり、部屋を飾ったりする感覚を楽しみたい。 | 本の配置、棚の色や素材、小物を組み合わせて編集できる。 |
| 好みが気になる人の選書から、次に読む本を探したい。 | 一冊だけでなく、その周囲の本や棚全体を眺めて積読に迎えられる。 |

## 3. 利用シーン

利用者は、何度も読み返す本、今も手放したくない本、これから読みたい本を選ぶ。中央には特に見せたい一冊を表紙向きに置き、隣には関連する本を並べる。棚の色を変え、小さな植物やブックエンドを添え、棚全体に名前を付ける。

できあがった棚のリンクを、SNSやブログのプロフィールに載せる。訪れた人は、紹介文を読む前に棚を見る。自分も好きな本の隣に知らない本を見つけ、選ぶと、その本の書誌情報と棚主の任意のひとことが開く。「積読に迎える」を押すと、自分の積読にその本が加わり、出会った棚を後からたどれる。

その本を読んだ後も、棚に飾るかどうかは本人が選ぶ。読了した本をすべて自動で並べるのではなく、残しておきたい本を選んで自分の棚を育てる。

**本を選ぶ → 棚を飾る → 自己紹介として見せる → 他人の棚を訪ねる → 気になる本を積読に迎える。**

自分の棚を作るところまでは一人でも楽しめる。他人の参加によって、本を見つける経路が増えていく。

## 4. サービス内容

### 4.1 選書と装飾で本棚を作る

書名・著者名などで本を探し、棚に置く。検索で見つからない本は手入力でも登録できる。蔵書の一括登録や長い自己紹介の入力を求めず、好きな本を一冊置くところから始められるようにする。

本の順番、表紙向き・背表紙向き、平積みを選び、棚の色・素材、背景、小物、余白を組み合わせる。同じ本を選んでも、並べ方と装飾によって異なる棚を作れる。装飾は初期版から含め、後付けの付加機能にはしない。

編集は棚板に沿って配置する2D方式を基本とし、細かな座標指定を要求しない。スマートフォンでは本を選んで配置先を指定する操作も用意する。書影が用意できない本には、書名と著者名を使った文字表紙を表示する。

棚の名前や、本との関係を示すひとことは任意とする。星の数や書評を書かなくても棚は完成する。

### 4.2 本棚そのものをプロフィールにする

共有ページでは本棚を最初に表示し、表示名と短い紹介を添える。棚を作った人が決めた並び順を、閲覧時にも保つ。人気順や更新順で本を自動的に並べ替えない。

作成中の棚は非公開とし、本人が公開を選んだ棚だけを閲覧・発見の対象にする。非公開への変更も可能にする。公開棚のリンクは、アカウントを持たない人も閲覧できる。

すべての登録本を公開棚へ載せる必要はない。「手元に登録していること」と「自己紹介として見せること」を分ける。未読の本も飾れるが、配置しただけで読了扱いにはしない。

### 4.3 本棚を訪ねて本を見つける

他人の棚は、共有リンク、書名・棚名の検索、公開棚の一覧から訪ねられる。棚の一覧では、書名の羅列だけでなく、選書と装飾が見える棚全体のプレビューを表示する。

本を選んだときは、その本の情報と、棚主が添えたひとことを表示する。周囲にどの本が並んでいるかを見ながら、読むかどうかを考えられる構成にする。

気に入った棚は保存して、後から再訪できる。初期版ではメッセージの送信やフォローを、本を持ち帰るための条件にしない。

### 4.4 気になる本を積読に迎える

他人の棚にある本から「積読に迎える」を選ぶと、自分用の積読に書誌情報を保存する。ここでの積読は、購入済みかどうかを問わず、あとで手に取りたい本の置き場とする。

元の棚から本は消えない。本そのものの貸借・購入や、電子書籍本文の取得も行わない。棚主の紹介文や装飾を自分の作品として複製する機能にはしない。

出会った棚への参照を自分用に残し、その棚が公開されている間は再訪できる。元の棚が非公開・削除になった場合は、棚主の情報や紹介文を保存先から再公開せず、自分が追加した書誌情報は保持する。

積読は初期状態では非公開とし、棚主への個別通知もしない。読了期限や催促は設けず、公開棚に飾るかどうかも本人が選ぶ。

## 5. 既存サービスとの位置づけ

本棚の作成や共有そのものには既存の選択肢がある。ブクログは本棚の作成、プロフィールのカスタマイズ、SNSでの共有を案内している。読書メーターも読書の記録・管理と、読書仲間とのつながりを提供している。したがって、「本を登録して他人に見せられる」だけを差別化の根拠にはしない。

Shelfieが重点を置くのは、**選書・配置・装飾を一体の自己紹介として仕上げ、その人の棚を眺めながら次の本を選ぶこと**である。装飾の種類を増やすだけでなく、見せたい本を選ぶ、余白を残す、本同士を隣に置く、といった編集に意味を持たせる。

初期の比較検証では、同じ選書を使った書籍一覧と装飾付き本棚を提示し、「自分を紹介するために人へ送りたいか」「棚を見て気になる一冊を選べるか」を確かめる。

比較対象：ブクログ公式ヘルプ「自分だけのオリジナル本棚を作ってみよう！」、読書メーター公式ヘルプ。確認日：2026年9月7日。

- ブクログ：https://booklog.zendesk.com/hc/ja/articles/33869909612311
- 読書メーター：https://bookmeter.com/help

## 6. 初期版の開発範囲

初期版の到達点は、**一人が装飾付きの棚を作り、別の人がその棚を訪ね、本を自分の積読へ迎える一連の体験が成立すること**とする。

| 領域 | 初期版に含める内容 |
| --- | --- |
| 本棚作成 | 一人につき公開用の本棚1つ。本の登録、配置、取り外し、任意の棚名・ひとこと。 |
| 装飾 | 少数の棚・背景テーマ、配置できる小物、表紙・背表紙・平積みの表示。 |
| 公開・共有 | 非公開での編集、公開切替、公開棚の共有リンク、未登録者による閲覧。 |
| 棚巡り | 公開棚のプレビュー、書名・棚名からの検索、気に入った棚の保存。 |
| 積読 | 他人の棚からの追加、自分用の一覧、出会った棚への参照、公開棚への配置。 |
| 利用基盤 | アカウント、保存・再開、公開範囲の制御、不適切な公開内容の通報。 |

複数の展示棚、過去の棚の保存、装飾素材の追加販売、書店・作家との特集は、基本体験を検証した後の拡張候補とする。

読書クイズ、読了数・連続利用の競争、性格の自動診断は採用しない。高度な推薦、コメント欄、DM、3D空間は初期版の対象外とする。

## 7. 実施・導入計画

初期提供形態は、スマートフォンとPCのブラウザで利用できるWebアプリを想定する。共有リンクから閲覧までの手順を短くし、アプリのインストールを閲覧条件にしない。

| 段階 | 実施内容 | 次の段階へ進む判断 |
| --- | --- | --- |
| 体験試作 | 選書・配置・装飾・公開棚の閲覧・積読追加を試作する。 | 操作説明に頼らず棚を作れ、自分のプロフィールとして使いたいという評価が得られるか。 |
| 小規模試用 | 棚を作る人と、その棚を訪ねる人の両方に使ってもらう。 | 棚が共有され、訪問先で本を見つけて積読に迎える行動が起きるか。 |
| 初期公開 | 書誌登録、保存、公開範囲、通報対応を整えて提供する。 | 誤公開やデータ消失を防ぎ、問い合わせに対応できるか。 |

初期の利用者は、選書に関心のある読者や読書会などから募る。本人の同意を得た棚を紹介し、それぞれがSNSやブログのプロフィールで共有する形で利用を広げる。参加者が増える前でも、自分の棚を作って見せる用途で利用が成立するようにする。

企画・画面設計、開発、装飾素材制作、書誌データの利用確認、運用を担当する体制を組む。個人開発では兼任を前提とする。公開時期と開発予算は、体験試作の結果と担当体制に基づいて見積もる。

## 8. 収益と費用の考え方

収益案は、基本機能を無料で提供し、追加の棚・背景・小物を装飾セットとして販売する方式とする。無料の範囲でも、自分らしい棚を作り、公開し、他人の棚から積読へ本を迎える体験を完結させる。

課金の有無で公開棚の露出や利用者の評価を優遇しない。価格や販売単位は、装飾への需要と制作費を確認して決める。

費用は、初期の開発・装飾素材制作費と、継続的な配信・データ保存・書誌情報利用・運用対応の費用に分ける。初期は装飾数と提供機能を絞り、継続利用の実態を見て拡張する。

## 9. 成果の評価

評価対象は、自己紹介として使える棚ができたか、その棚が本との出会いにつながったかである。読了冊数や毎日の起動回数を主な成功指標にしない。

| 検証する価値 | 確認方法 |
| --- | --- |
| 自分らしい棚を作れる。 | 作成過程を観察し、選書と装飾のどこに本人らしさを感じるかを聞く。 |
| 自己紹介として使いたくなる。 | 実際の共有行動と、受け取った人の棚閲覧を確認する。 |
| 他人の棚から本に出会える。 | 他人の公開棚を閲覧した利用者のうち、そこから積読に追加した利用者の割合を確認する。 |
| 更新を強制せずに使い続けられる。 | 自分の棚、保存した棚、積読への再訪と、その利用理由を確認する。 |

数値目標は小規模試用で基準値を得てから設定する。共有率や追加率だけを高めるために、公開や読書を催促する設計にはしない。

## 10. 主なリスクと対策

| リスク | 対策 |
| --- | --- |
| 棚を作る操作が難しく、自己表現より作業負担が大きくなる。 | テンプレートと配置補助を用意し、少数の本でも棚が整うようにする。 |
| 装飾で書名が読めない、スマートフォンでは選びにくい。 | 装飾の配置範囲を制限し、文字表示と一覧表示を併用する。 |
| 見せるつもりのない本や積読が公開される。 | 登録・積読と公開棚を分け、公開前のプレビューを用意する。 |
| 書影・書誌情報・装飾素材を想定どおり利用できない。 | 取得元の利用条件を確認し、利用できない画像は文字表紙や自作素材で代替する。 |
| 人気や読書量を競う場になり、棚づくりの趣旨から離れる。 | 人気ランキング、連続利用報酬、積読の催促を設けず、選書と棚の閲覧を中心に置く。 |
