## 1. 企画の位置づけ

**Shelfie は、商品カードの組合せと得点の成長を楽しむゲーム企画である。** 2026年6月6日の会話で、複数のゲーム企画から Shelfie を採用し、実際に遊べる試作品を作る方針が示された。［S1・S2］

関連資料として確認できた「レシート・ローグ：閉店前の精算迷宮」では、閉店前のコンビニ風店舗を舞台に、商品カードをレシートに並べ、役・備品・クーポンを組み合わせてノルマ達成を目指す。ジャンルは「ローグライト × レジ精算／レシート計算 × 軽量デッキ構築」である。［S3］

ただし、試作の報告には「5スロットのレシート」と異なる「5×5の棚」の記述もある。**両者を混ぜたルールを作らず、本書では資料に残るレシート案を詳述し、Shelfie の最終仕様との対応は未確認として扱う。** 過去資料の題名がそのまま改題されたのか、別の候補案なのかも、名称だけから断定しない。

## 2. 目指す体験

既存資料では、身近な商品や会計を入り口にして、組合せによる大きな倍率成長を楽しむことが狙いとして挙げられている。スロットやポーカーよりギャンブルの連想を弱め、モバイル・PCの双方で短時間に遊べる方向を目指している。これは企画上の意図であり、市場調査やプレイテストで効果を確認したという意味ではない。［S3］

この狙いを実装時の評価軸に整理すると、次のようになる。

- 商品を選ぶときに、価格だけでなく、組合せや手持ちの効果との相性を考える余地がある。
- 精算後に、どの役や効果が得点を伸ばしたか分かり、次の選択に生かせる。
- 備品やクーポンによって、同じ商品でも使い方が変わり、ランごとに異なる構成を試せる。
- 通常のノルマに加え、ボスや制約によって、それまでの構成を見直す場面がある。

これらは今回の整理案である。対象年齢、1ランの所要時間、販売形態、対応ストア、収益化方式は、取得できた記録からは確定できない。

## 3. レシート方式のゲーム設計

本節は、関連する既存資料の内容をまとめたものである。5×5の棚方式を採用する場合は、盤面・役判定・操作を含めて見直す。［S3］

### 3.1 商品を5スロットに並べる

プレイヤーは商品カードを5スロットのレシートに並べる。得点には、商品自体に加えて、カテゴリ役、価格役、備品の効果、クーポンによる倍率が関わる。

| 要素 | 資料から確認できる役割 | 詳細の取得状況 |
| --- | --- | --- |
| 商品カード | レシートに並べる基本要素。カテゴリや価格を用いた判定の対象になる。 | 個別カードの属性・値は未取得。 |
| カテゴリ役 | 商品カテゴリに基づく役判定。 | 役の一覧、成立条件、重複時の扱いは未取得。 |
| 価格役 | 商品価格に基づく役判定。 | 役の一覧、成立条件、評価値は未取得。 |
| 備品／常駐アイテム | 継続的な効果によって商品や得点の組合せを変える要素。 | 効果本文、装備枠、発動順序は未取得。 |
| 消耗品クーポン | 消費して使う効果。資料では倍率への関与が示されている。 | 使用タイミング、対象、重ね掛けの条件は未取得。 |
| ノルマ・敵・ボス | 得点を伸ばす目標や制約となる要素。 | 個別効果、出現順序、達成判定は未取得。 |

「5スロット」はレシートの枠数であり、売場の候補数やデッキ枚数とは別の数量として扱う。また、並び順そのものが役に影響するかどうかは、枠数だけからは決めない。

### 3.2 得点の基本形

既存資料では、次の基本形が示されている。［S3］

```text
スコア = 小計 × レジ倍率 × 満足倍率
          Chips   Mult       xMult
```

スコアは整数として扱う方針である。ただし、この式だけでは計算処理は一意に定まらない。商品価格や役の値を小計へ加える順序、レジ倍率への加算と乗算、満足倍率の累積方法、端数処理、複数効果の発動順序は、元のスコア仕様・参照実装との照合が必要である。

実装時には、最終得点だけでなく、商品、成立した役、備品、クーポンがそれぞれどう寄与したかを追える計算結果を残すことを提案する。これは得点表示とテストの両方に利用できる。

### 3.3 1ランの流れの整理案

既存資料と試作報告に登場する機能を、プレイの流れとして整理すると以下になる。厳密な状態遷移や各フェーズの回数を確定するものではない。［S3・S4］

| 段階 | プレイヤーの行動 | 実装前に確定する点 |
| --- | --- | --- |
| 商品を選ぶ | 提示された商品と現在の構成を見比べ、使用・購入する商品を選ぶ。 | 配布と購入の区別、候補数、所持金、デッキへの加入方法。 |
| レシートを組む | 商品を5スロットに配置し、狙う役や使う効果を選ぶ。 | 空き枠の可否、並び順、入替え・捨て札・再抽選の条件。 |
| 精算する | 役と各効果を適用して得点を得る。 | 効果の発動順序、クーポンの消費時点、得点の累積方法。 |
| 結果を受け取る | ノルマとの比較結果を確認し、報酬や購入を通じて構成を調整する。 | 判定タイミング、報酬、購入可能な要素、持越し条件。 |
| 次の課題へ進む | 次のノルマやボスに挑む。 | ステージ構成、ボスの位置、ランの勝利条件と敗北条件。 |

初期資金、初期デッキ、制限ターン数、精算可能回数、未達時の扱いは、本書では補完しない。

## 6. MVPと開発順序の整理案

本節は、過去の設計要素を実装へつなぐための提案である。既存の `docs/14_mvp_backlog.md` の本文を再現したものではない。

### 6.1 最初に確かめること

まず、最終的に採用する盤面方式と、それに対応する試作品・スコア仕様を照合する。そのうえで、「商品を選ぶ → 組み合わせる → 得点の理由が分かる → 次の選択を変えたくなる」という体験を少数の商品で検証する。

完成版のカード数を先に満たすことは、最初の到達目標にしない。

### 6.2 実装と検証の単位

| 順序 | 作業 | 完了を判断する基準 |
| --- | --- | --- |
| 1 | 盤面方式とルールの版を揃える。 | 盤面、役判定、スコア、勝敗条件が同じ仕様に基づいている。 |
| 2 | 得点計算を単独で再現する。 | 固定した商品・効果・状態から、期待した整数得点と計算内訳が得られる。 |
| 3 | 最小の1ラウンドを遊べるようにする。 | 商品選択から結果表示まで進み、確定した規則に基づいて達成・未達を判定できる。 |
| 4 | 構成を変える要素を入れる。 | 少数の備品・クーポンによって、狙う商品や役を変える理由が生じる。 |
| 5 | ラン進行をつなぐ。 | 複数の課題、報酬・購入、ボス、終了・再開の状態が矛盾なく遷移する。 |
| 6 | 入力と保存を整える。 | 対象とする端末で操作でき、保存・読込後に進行と所持品が一致する。 |

得点計算の検証では、役が成立しない場合、複数の役が成立する場合、備品とクーポンが同時に作用する場合を含める。どの結果を正解とするかは、先に確定したルールに基づく。

### 6.3 技術選定の扱い

過去の試作報告から確認できるのは、ブラウザ実行と `localStorage` 保存という範囲である。ゲームエンジン、フレームワーク、実装言語、配信方式は確定仕様として記載しない。

本書ではゲームの企画・実装に必要な内容だけを扱い、別企画のSNS機能や技術構成を流用しない。
